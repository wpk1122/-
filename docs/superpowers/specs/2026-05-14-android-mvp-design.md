# AI 智能日程助手 Android MVP 设计

## 背景

项目包中的方案定位是“会理解、会整理、会学习用户节奏”的 AI 个人时间助理。MVP 先做可运行的 Android 原生应用，覆盖第一阶段能力：一句话输入、任务解析、用户确认加入日程、本地保存、基础提醒。后续再扩展行为学习、夜间复盘、系统日历和云同步。

## 目标

- 构建一个 Android 原生 MVP，可在本地开发环境中编译运行。
- 用户可以用自然语言输入日程需求，并看到解析后的结构化任务。
- 用户确认后，任务保存到本地数据库，并可在日程列表中查看。
- 对带有时间的任务创建基础提醒通知。
- 使用项目包中的“蓝色时间规划少女”形象作为品牌视觉资产。
- 将缺失的构建工具尽量安装到项目目录下，避免依赖全局环境。

## 非目标

- MVP 不直接接入真实大模型服务；先使用本地规则解析器，并预留 AI 解析接口。
- MVP 不实现夜间复盘、长期学习评分模型、云同步、语音输入、多设备同步。
- MVP 不强行修改用户日程；所有自动建议在后续阶段也必须经过用户确认。

## 推荐方案

采用 Kotlin + Jetpack Compose + Room + WorkManager。

这个组合适合快速做出原生 Android 应用：Compose 负责界面，Room 负责本地任务数据，WorkManager 负责可持久化的提醒调度。解析能力通过接口隔离，先用规则解析器跑通 MVP，以后可以替换为大模型 API。

## 应用结构

项目根目录计划创建 Android 工程目录 `ChronaAndroid/`。

主要模块如下：

- `MainActivity`：应用入口，承载 Compose UI。
- `ScheduleInputScreen`：一句话输入、解析结果预览、确认加入日程。
- `ScheduleListScreen`：展示已保存任务，支持完成、删除、推迟等基础操作入口。
- `TaskParser`：解析接口，输入自然语言文本，输出结构化候选任务。
- `RuleBasedTaskParser`：MVP 本地解析实现，支持“明天、今晚、周末、周六、上午、下午、晚上”等常见中文表达。
- `ScheduleTaskDao` / `AppDatabase`：Room 数据访问层。
- `ReminderScheduler`：提醒调度接口，底层使用 WorkManager。
- `ReminderWorker`：到点创建 Android 通知。
- `ChronaTheme`：Compose 主题，使用蓝白为主，辅以少量高对比色，避免整屏单一蓝色。

## 数据模型

MVP 只落地核心表 `ScheduleTask`：

- `id`: 自增主键。
- `title`: 任务标题。
- `note`: 可选备注，保存原始输入片段或解析说明。
- `startAt`: 开始时间，毫秒时间戳，可为空。
- `endAt`: 结束时间，毫秒时间戳，可为空。
- `status`: `pending`、`done`、`deleted`。
- `sourceText`: 用户原始输入。
- `createdAt`: 创建时间。
- `updatedAt`: 更新时间。

行为学习阶段需要的 `NotificationRecord`、`UserBehaviorLog`、`TimeSlotStat`、`InferredFreeTimeSlot`、`UserPreferenceProfile` 暂不建实体，避免 MVP 过重。完成、推迟、删除等操作可以先在 `ScheduleTask` 上保留最小状态，后续再扩展为行为日志。

## 数据流

1. 用户在首屏输入一句话。
2. `TaskParser` 将文本拆成候选任务。
3. UI 展示候选任务列表，用户可确认加入。
4. Repository 写入 Room 数据库。
5. 对有 `startAt` 的任务调用 `ReminderScheduler`。
6. WorkManager 到时触发 `ReminderWorker`。
7. Worker 发送通知，点击通知回到应用。

## UI 设计

首屏直接进入可用体验，不做营销落地页。

界面包含：

- 顶部轻量品牌区：Chrona 名称、人物形象缩略图、今天日期。
- 输入区：多行文本框和解析按钮。
- 解析结果区：每条候选任务显示标题、时间、置信说明，提供确认加入。
- 今日/近期列表：展示保存后的日程任务和状态。
- 空状态：使用项目包人物图和一句简短提示。

视觉风格以清爽、可靠、可扫描为目标。蓝白是品牌基调，但按钮、状态和提醒使用不同色相做区分，避免界面只有一种蓝。

## 解析规则

MVP 解析器以稳定可解释为优先：

- 用逗号、顿号、分号、换行、“然后”等拆分事项。
- 识别相对日期：今天、明天、后天、周末、周六、周日。
- 识别时间段：早上、上午、中午、下午、晚上、今晚。
- 识别具体时间：`15:00`、`下午3点`、`晚上8点`。
- 未识别具体时间时，按上下文给默认时间，例如“拿快递”默认下午，“健身”默认晚上，“写报告”默认周末下午。
- 无法判断日期或时间时仍生成任务，但标记为待确认时间，不创建提醒。

默认时间只是 MVP 辅助，不代表系统替用户决定。UI 必须让用户在加入前看到解析结果。

## 提醒与权限

应用首次需要提醒时请求通知权限。Android 13 及以上使用 `POST_NOTIFICATIONS` 权限。WorkManager 负责调度提醒任务；如果系统限制导致提醒延迟，MVP 先接受近似提醒，后续阶段再评估精确闹钟权限。

通知内容包含任务标题和时间。点击通知打开应用任务列表。

## 环境与工具链

先检测本机是否已有 JDK、Gradle、Android SDK。缺失时优先安装到项目目录：

- `.tools/jdk/`
- `.tools/gradle/`
- `.tools/android-sdk/`

提供 PowerShell 脚本：

- `scripts/setup-android.ps1`：下载或配置项目内工具链。
- `scripts/build-android.ps1`：使用项目内工具链构建 Debug APK。

如果网络或许可协议阻止自动安装，脚本要给出明确错误和下一步提示。

## 错误处理

- 解析为空：提示用户换一种表达，并保留输入。
- 数据库写入失败：显示错误提示，不清空解析结果。
- 通知权限未授予：任务仍可保存，只是不创建提醒，并提示用户可稍后开启。
- 调度失败：任务保存成功，列表显示提醒未启用状态。
- 环境安装失败：保留已下载文件，输出失败步骤，允许重复运行 setup 脚本。

## 测试策略

- 为 `RuleBasedTaskParser` 添加单元测试，覆盖“明天拿快递、晚上健身、周末写报告”等中文输入。
- 为 Repository/DAO 添加基础 Room 测试，验证任务保存和查询。
- 构建阶段至少运行 Gradle test 或可用的等价验证。
- 如果本机 Android SDK 无法完整安装，至少确保工程结构、Gradle wrapper 或项目内 Gradle 配置明确，并记录未完成的环境原因。

## 后续扩展

- 接入大模型 API，实现更强的自然语言解析。
- 增加 `UserBehaviorLog`，记录完成、推迟、忽略通知、删除、修改时间。
- 实现 `TimeSlotStat` 和 30 分钟时间段评分。
- 加入夜间复盘和次日建议确认流程。
- 接入系统日历、语音输入、云同步和周报/月报。
