# Chrona C-2 真实使用版设计

## 背景

用户已选择“完整陪伴式助手”的真实使用版。这个版本不是只做演示 UI，而是让 Chrona 在手机本地记录真实日程行为，并逐步形成可解释的个人节奏建议。角色融合终版包提供首页、AI 对话、提醒执行、总结优化四个场景；API 长文本稳定性方案包补充了长文本分批、上下文压缩、重试降级和固定 JSON 输出的工程边界。

## 目标

- 把角色从静态装饰升级为四个可用场景：首页问候、AI 对话确认、提醒执行、总结优化。
- 记录真实用户行为：创建、完成、删除，后续可扩展推迟、忽略提醒、修改时间。
- 在本地生成基础行为洞察：完成率、今日进度、高效时段、风险时段、明日建议。
- API 分析保持可选：默认本地分析；用户配置 API 后，只上传压缩摘要，不上传完整历史明细。
- 长文本输入超过 800-1000 字时进入分批解析，避免“字一多 API 就不可用”。
- 保持当前 APK 可构建、可安装、可离线回退。

## 非目标

- 不做云同步和账号系统。
- 不上传完整用户行为明细。
- 不实现完整后端服务；当前版本仍为端侧架构。
- 不实现复杂动画引擎；角色动效先用轻量图片、状态文案和局部视觉变化表达。

## 推荐架构

采用端侧优先架构：Room 保存日程和行为事件，Repository 负责写入状态和行为日志，Insights 引擎从本地数据计算摘要；API 层只负责自然语言事项提取和可选总结文案增强。复杂长文本不再一次性请求模型，而是先预处理分段，再逐段提取事项，最后由本地规则做时间标准化、冲突检测和降级。

## 数据模型

保留 `ScheduleTask` 作为任务主表，新增 `TaskBehaviorEvent` 行为事件表：

- `id`: 自增主键。
- `taskId`: 关联任务 ID，可为空，用于后续全局事件。
- `type`: 字符串事件类型，首版包含 `CREATED`、`COMPLETED`、`DELETED`。
- `occurredAt`: 事件发生时间毫秒。
- `metadata`: 可选 JSON 文本，后续记录推迟分钟数、提醒响应等。

`ScheduleRepository` 在创建、完成、删除任务时同步记录事件。这样后续总结和长期优化不依赖 UI 临时状态，而是有可重放的行为历史。

## 本地洞察

新增纯 Kotlin 洞察引擎，根据任务和行为事件生成 `ScheduleInsight`：

- 今日任务总数。
- 今日已完成数量。
- 完成率。
- 最常完成的本地小时段。
- 待完成风险数量。
- 2-4 条中文建议。

首版只用本地规则：完成事件越集中的时段越像高效时段；过期未完成任务会提高风险提示；无历史时给温和默认建议。这个引擎必须可单元测试。

## API 长文本稳定性

API 解析采用分层策略：

1. 长度判断：超过 900 字进入分批流程。
2. 分段规则：优先按日期标题、换行、句号、分号和中文逗号拆分；单段尽量控制在 900 字以内。
3. 固定输出：模型只返回任务 JSON 数组，不自由生成长篇说明。
4. 输出限制：请求体加入 `max_tokens`，默认 900，避免长输出中断。
5. 上下文压缩：系统提示只带当前时间、时区和简短规则，不带完整历史明细。
6. 降级策略：单段失败时跳过该段并让 `ScheduleParseService` 回退本地规则；整体失败保留输入和本地解析。

AI 负责理解和表达，本地负责规则、时间标准化、冲突检测、保存和提醒。以后要做 API 总结时，只发送本地洞察摘要和近期统计，不发送完整任务正文列表。

## UI 场景

首版将当前单页体验升级为四个场景入口：

- 首页：角色问候、今日进度、一句话输入、近期任务。
- AI 对话：展示输入、解析结果、确认加入和追问提示。
- 提醒执行：展示待执行任务、完成按钮、删除按钮、执行反馈文案。
- 总结优化：展示本地洞察、完成率、高效时段、建议列表，并预留可选 API 总结增强入口。

素材使用角色融合终版包中的四张场景图，复制为 Android drawable 资源，并按场景使用。界面配色以角色蓝白为底，加入金色、绿色和粉色作为状态色，避免整屏单一蓝。

## 错误处理

- API 未配置：本地解析和本地总结仍可使用。
- API 长文本失败：提示内容较多已分批或回退，本地保留输入。
- JSON 解析失败：只返回最小 JSON 重试的能力后续扩展，首版回退本地规则。
- 行为日志写入失败：不阻止任务状态更新，但测试中要保证正常路径写入。
- 数据库迁移：从版本 1 到 2 创建行为事件表，保留已有任务。

## 测试策略

- 为长文本分段和 API 请求体添加单元测试。
- 为行为事件写入添加 Repository 单元测试。
- 为本地洞察引擎添加单元测试，覆盖有完成历史和无历史两种情况。
- 构建阶段运行 `scripts/build-android.ps1`，确保测试和 debug APK 构建通过。
